# iCloud 同步排障与安全恢复手册

本手册供用户支持和发布值班使用。核心原则只有三条：不删除唯一副本、不静默切换存储模式、不要求用户直接修改 iCloud 容器或迁移文件。

## iCloud 不可用

症状包括“iCloud Drive 不可用”、容器无法打开，或账号变更后同步停止。

1. 暂停编辑相关文稿，确认设备已登录预期 Apple 账号且 iCloud Drive 已开启。
2. 在系统“文件”App 中检查能否看到 iCloud Drive 与 Hashmark 文件夹。
3. 检查网络、设备可用空间和 iCloud 可用额度，然后回到 Hashmark 设置页点“重试”。
4. Hashmark 会保持已承诺的 iCloud 模式并冻结写入，不会偷偷改用一个新的本地目录。
5. 如果账号刚切换，先确认新账号确实应接管此设备，再重试。不要在两个账号之间反复切换并同时编辑。

## 下载或上传长时间没有完成

- 保持设备联网、Hashmark 在前台，并在可能时连接电源。
- 在“文件”App 中打开同一文稿，观察系统是否仍显示下载或上传状态。
- 确认可用设备空间和 iCloud 配额；释放空间后再点“重试”。
- 不要通过删除 Hashmark、删除 iCloud 文件夹或清空系统缓存来“强制刷新”。删除 App 可能同时移除尚未迁移的本地文稿和恢复材料。
- 若单个文件持续失败，记录相对路径、文件大小、错误文案和发生时间，但不要把文稿正文或 API Key 放进普通工单。

## 开启或关闭同步失败

Hashmark 的切换是事务性的：先生成独立恢复副本并校验 SHA-256，再合并，最后才提交模式。

- 提交前失败：原模式和原文稿仍是主副本，可在空间/网络/配额恢复后直接重试。
- 提交后失败：新模式已经生效，旧位置可能作为清理债务暂时保留；下次启动会继续幂等清理。
- 恢复副本保存在 App 的 Application Support 中且不会出现在文稿列表。支持人员不得指导用户手动删除或编辑它。
- 关闭 iCloud 会先下载并验证本地副本，而且永远不会删除云端文稿。
- 如果 UI 持续显示迁移错误，保留 App 和两侧文稿原状，收集安全诊断后升级给开发人员。

## 冲突副本

同一路径出现不同内容时，Hashmark 会保留带 `Conflict`、设备名和时间的同级副本；正在编辑的草稿收到远端变更时，也会先保留远端内容再保存草稿。

1. 分别打开主文稿和冲突副本，人工比较并合并需要的段落。
2. 确认最终文稿已在另一台设备或“文件”App 中可见。
3. 只有在确认内容已合并且存在第二份可验证副本后，才删除不再需要的冲突文件。
4. 不要仅凭文件名或修改时间批量删除冲突副本。

## 远端删除正在编辑的文稿

- 干净文稿会关闭并提示已从其他位置删除。
- 有未保存改动时，Hashmark 会在当前文稿库根目录创建 `Recovered` 副本，而不会重新创建被远端删除的旧路径。
- 若恢复写入失败，保持编辑页打开，释放空间或恢复访问后点“重试”；在恢复成功前不要强制结束 App。

## 安全关闭与重新启用

- 关闭同步后，本设备使用已验证的本地副本，iCloud 文稿仍保留供其他设备使用。
- 重新启用会按相对路径合并；相同 SHA-256 内容去重，不同内容都保留。
- 在多设备同时切换模式前，先等待当前设备的迁移状态结束。

## 可收集的安全诊断

可以记录：Hashmark 版本/构建号、iOS/iPadOS 版本、设备型号、设置页显示的存储模式和错误、操作方向、发生时间、文件相对路径与大小、设备/iCloud 剩余空间，以及问题能否在“文件”App 复现。

不得收集：AI API Key、完整文稿正文、用户 Apple ID 密码、iCloud 身份令牌、签名 profile 私钥或未经用户明确同意的附件内容。

升级开发处理时，应优先检查迁移 journal 的方向/checkpoint、恢复 manifest 是否可验证、cleanup debt、容器身份是否变化、下载错误和文件 presenter 事件顺序。任何修复都必须先复制并验证，再允许删除冗余副本。
